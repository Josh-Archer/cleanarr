# v0.2.58

Requires an Arr import event before stale stopped torrent cleanup when
`CLEANARR_STALE_TORRENT_REQUIRE_IMPORT=true`. Cleanup removes only the
Transmission record and preserves downloaded data. Missing API access or
unmatched history keeps the torrent. Ignored-download events do not qualify.

The stopped predicate accepts the string status returned by transmission-rpc,
covered by a test using real Torrent objects rather than numeric mock statuses.

## Architecture review

Reviewed the changed cleanup path against the architecture gate. Shared logic
remains in `cleanarr/`; the cronjob harness and public interfaces retain their
existing boundaries. Configuration is generic and documented. Releases remain
versioned from `pyproject.toml` and downstream consumers use published images.

## Security review

Reviewed the changed path against the security gate. It requires a matching
import event, a complete stopped torrent, the configured age threshold, and the
existing ownership filters. API failures keep data. Removal explicitly uses
`delete_data=False`. No credentials or deployment-specific endpoints were added
in this release. The public safety scan and unit suite are required before
publishing; CI also builds all images.
